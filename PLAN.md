## Текущее состояние (кратко)

- **pkg-rs**: сканирование package.py, резолвер (PubGrub/Rez), env/evars, запуск приложений, build, pip import, GUI, rez-команды (часть нативно, часть passthrough в Python rez).
- **bin-patch** (`crates/bin-patch`): ELF/Mach-O in-place патчинг для релоцируемых бандлов, без patchelf/install_name_tool.
- **Windows**: санитизация путей к python/pip в скриптах после pip-импорта.

## Приоритетные задачи (по порядку)

### 1. Выполнение команд пакета при `pkg env` (Rez parity)

**Сейчас:** при `pkg env` применяются только env/evars из package.py. Поля `pre_commands`, `commands`, `post_commands` не выполняются.

**Цель:** как в Rez — после резолва контекста выполнять pre_commands → commands → post_commands (rex-подобно), мержить изменения окружения и отдавать итоговый env (или запускать приложение в нём).

**Шаги:**
- Определить, где в коде формируется env для `pkg env` (команда env, effective_env и т.д.).
- Добавить этап выполнения команд пакета (и зависимостей?) с передачей текущего env и мержем результата.
- Учесть порядок: pre_commands (deps + self), commands (deps + self), post_commands (deps + self) — по документации Rez.
- Не ломать текущий поток: если команд нет, поведение как сейчас.

**Файлы:** `src/package.rs` (_env, effective_env), `src/env.rs`, команда `pkg env` (например `src/pkg/commands/env.rs`), при необходимости loader/commands capture (pre_commands/commands/post_commands уже извлекаются при загрузке package.py — см. AGENTS.md).

---

### 2. Тесты пакетов (pre_test_commands + тестовые записи)

**Цель:** выполнение `pre_test_commands` и записей из секции `tests` с отчётом (Rez parity для тестирования пакетов).

**Зависимости:** после п.1 логика выполнения команд из пакета уже есть; остаётся отдельный режим/команда для тестов и парсинг секции tests.

---

### 3. Passthrough-команды и rez-next

**Сейчас:** часть команд (`rez bind --list/--search`, `rez context` с неизвестными флагами, `rez status`, `rez suite` в части кейсов) уходит в Python rez через passthrough.

**Цель:** по возможности заменить passthrough на нативную реализацию или на код из rez-next.

**Шаги:**
- Сверить список passthrough-команд и флагов с реализациями в `_ref/rez-next/src/cli/commands/` (bind, context, status, suite, search и т.д.).
- Для каждой такой команды: либо перенести/адаптировать логику из rez-next, либо явно оставить passthrough с пометкой в коде/документации.

---

### 4. Пути к python/pip на Windows

**Цель:** нигде не записывать и не «пробивать» абсолютные пути к python/pip в конфиги/скрипты под установку (python-environments, modules, packages), чтобы не ломать переносимость.

**Уже сделано:** санитизация в скриптах после pip-импорта.

**Дополнительно:** при появлении багов — искать места, где пути могут попадать в конфиг или в файлы репозитория, и править (не писать абсолютные пути или релативизировать при бандле).
